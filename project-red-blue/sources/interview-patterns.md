## 来源权重

```text
REAL_SELF_INTERVIEW
    用户自己的真实面试。最高权重，优先决定下一轮攻击。

TARGET_ROLE_JD
    决定哪些能力是岗位必须验证的，而不是靠通用题库猜。

HIGH_SIGNAL_PUBLIC_RECORD
    长追问链、项目细节密度高、与 Agent/RAG/后端/后训练强相关的真实公开记录。

GENERAL_PUBLIC_RECORD
    用于补充基础题与提问风格，不直接决定 Zuno 的 Gap。
```

公开面经只能回答“面试官可能如何问”，不能回答“Zuno 实际做过什么”。

## 从真实面经提炼的稳定行为

当前来源支持以下行为模式：

1. **项目题与基础题并存**：有的面试从项目一路深挖，也存在完全不聊项目、直接 Agent/RAG/Transformer/数据库/算法基础轰炸；
2. **Ownership 是真实性验证**：团队人数、谁做、本人哪段、部署/模型/数据由谁负责会被反复追问；
3. **Why/Why-not 比框架名更重要**：为什么用某方案、为什么不用成熟开源、为什么不是更简单方案；
4. **实现会被追到参数与数据**：Rerank Top-N/Top-M、阈值、字段、Schema、Token、缓存、MQ、索引和状态；
5. **成功结论会被追证据**：Baseline、Dataset、Metric、Bad Case、延迟、成本、上线、真实用户；
6. **架构复杂度会被业务规模反问**：小团队、小用户量和未上线状态会触发过度设计、分布式和微服务必要性攻击；
7. **回答决定下一问**：真实高质量面试经常沿候选人刚说出的词继续打穿，而不是按固定题单平铺。
8. **架构与实施会被联动攻击**：面试官先问为什么这样设计，再问小团队能否实现、当前做到哪、谁维护和如何上线；目标架构不能绕过实施证据。
9. **岗位方向会改变攻击顺序**：Agent/RAG 岗位更容易从项目进入检索、Memory、Tool 和评测；Java/后端岗位可能从同一项目切到线程、网络、数据库、MQ、一致性和故障恢复；两条线不能互相替代。
10. **短记录只做弱信号**：缺少连续问答和上下文的记录可以补充题型关键词，但不能单独证明面试官的稳定行为。

## Zuno 映射规则

面试来源进入 Zuno 只允许形成：

```text
Attack Pattern
Interviewer Persona
Question Domain / Attack Angle
Gap Discovery Heuristic
Red Retest 换问法
```

不得直接形成：

```text
新的 Zuno Runtime 语义
新的 Current 实现结论
新的真实用户/团队/客户事实
未经架构确认的 Contract
未经测量的指标
```

## 记录方式

每条新模式如有必要进入本工作区，记录：来源仓库与路径、岗位或场景、首问、追问方向、面试官试图验证什么、可映射的 D/A 分类、是否来自用户本人、是否已经在真实 Red Retest 中复现。
