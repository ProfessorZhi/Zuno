## 当前 Target

- Python-only / Python-first 后端是 Owner Target Constraint。
- Microservice 是部署方向，但服务数量、物理边界和独立部署理由仍需证据。
- Legal Domain、Evidence、Runtime、Security、Eval 和部署之间的跨层关系由总体架构统一表达。

## 仍然是 Hypothesis 或 Gap

- Zuno 质量优于 WorkBuddy、Dify 或其他 Host。
- Domain-aware Runtime、Graph、Memory Provider、Multi-Agent 或自研服务边界产生可重复收益。
- 安全更可验证、成本更低、效率更高或更接近生产。
- 具体服务数量、队列/数据库物理拆分、模型 Gateway 和 Provider 选择。

## Reversal

若更简单的 Host + Legal Backend、Hybrid Retrieval、单 Agent + 并行工具或模块化服务 + Worker 在同等数据、模型和预算下达到同样质量与恢复边界，对应自研复杂度应被缩减、外部化或删除。
