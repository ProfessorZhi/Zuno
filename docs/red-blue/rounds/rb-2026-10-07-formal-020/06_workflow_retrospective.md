**做错的 / 需要管的地方：**

**Skill 规则建议：**

- **新发现**：Red 的攻击框架会被**它自己参与制定的治理文档**污染。见 §4。

## 4. Harness Reflection

这一节是本发明价值最高的部分。

### 4.1 隔离的真实边界

**物理的部分是真的：** Red / Blue 各角色运行在独立上下文里，Red 的上下文里从来没有出现过 `src/` 的内容。Red Wave 1 的两个半批互不可见，拼缝处未做跨半批改写。

**不是物理的部分：** 文件系统是共享的。**允许读哪些文件靠指令约束 + 事后审计，不是沙箱。**

### 4.2 本轮实测出的三个泄漏向量

1. **目录元数据。** Red Final 为确认输入体量跑了一次 `ls -la`，回显了 `03_blue_architecture_notes.md` 和 `04_blue_wave2_architecture_notes.md` 的**文件名与大小**。它没有读内容，并主动披露。但这条通道是真实存在的 —— **「读过什么」和「看到过文件名」是两个不同的泄漏等级**，当前的 allowlist 只约束前者。
2. **并行写文件的可见性。** 候选人 agent 与架构 notes agent 同时写同一目录，候选人 agent 察觉到了另一个 agent 的存在并主动报告「未读取其输出」。内容隔离守住了，但**跨角色存在性**没有被隔离。
3. **治理文档双重身份。** `interview-acceptance-standard.md` 既是 Red 的攻击标准，也是 Blue 的答题模板。候选人读过它之后，**「边界」字段的形态被它塑造**（A183）。这是本轮最微妙的一条：它不是泄漏，是**标准本身同时充当了答案格式**。

### 4.3 盲测认证不到的东西

Red Final 自己写下了这一轮最重要的一句元判断：

> A113 宣称的「baseline 自己也漂了、provenance 原文禁止制造百分比」我核不了 —— **最漂亮的一次解矛盾，与高水平构造之间我没有判据。**

**盲 Red 无法区分「真的回去查了记录」与「被追问后临时构造了一个自洽解释」。** 我作为 Controller 能核（`project-fact-provenance.md:96` 原文确实写着这句），所以这一次判为通过。但**这暴露了 `strict_blind_red_certification: true` 的认证上限**：它认证的是「回答在盲态下自洽且不塌」，不是「回答来自查证」。

要认证后者，需要的东西不在这套流程里 —— 见 improvement ledger 的 `IMP-020-14`。

### 4.4 本轮实测出的一个方法论陷阱

**指标会被优化掉，然后换一个位置重新出现。**

第一轮 Red 把「候选人主动认边界」判为最强真实性信号。第二轮发现这个行为模式是治理文档教出来的。**这不是候选人在演戏，是这套流程自己把「诚实」变成了一个可优化的目标函数。**

对一个以「可追溯性」为唯一目标的项目来说，这是最需要记住的一条：**任何被写进标准的诚实形式，都会在下一轮退化成表演形式。** 应对方式不是取消标准，而是**持续更换测量点** —— 例如从「他认了多少边界」换成「他认的边界里有多少事后被证明是他自己造成的」。
